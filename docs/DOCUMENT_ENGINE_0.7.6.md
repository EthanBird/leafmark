# LeafMark 0.7.6 文档引擎

0.7.6 从稳定的 0.7.5 WebView2 / Tauri 架构继续开发，0.8.0 Native 实验线不作为本版本基线。目标是让“一叶”在保留 Markdown 完整编辑体验的同时，成为本地、快速、可恢复的通用文档阅读器。

## 打开流水线

1. Rust 校验路径、扩展名、文件类型和 512 MB 大小上限。
2. 首次打开 Office/PDF 时，Rust 将原件逐字节复制到应用数据目录，并把快照加入历史索引。
3. UI 立即建立文档标签。PDF 直接获得本地 asset URL；Office 在独立 Worker 中解析。
4. Word 只先返回前 160 个内容块；表格只返回活动工作表前 120 行、最多 160 列；演示只返回目录和当前页。
5. 用户滚动或切换工作表/幻灯片时，再从 Worker 内的解析缓存读取后续数据，不重复读取磁盘。
6. Worker 使用 4 文档 LRU；退出或淘汰后可从保留副本重新解析。

这套设计把“窗口可操作”和“整个文件完全解析”解耦。产品层面的性能目标是：普通本地文档在冷启动后 1 秒内出现可交互首屏，大文档先显示可操作的加载状态且绝不冻结主界面。该目标必须由 Release 构建在 Windows 真机上持续测量；在没有统一硬件、文档语料和竞品版本的对照数据前，不宣称未经验证的“市场第一”。

## 兼容矩阵

| 格式 | 内部查看 | 首屏策略 | 当前边界 |
| --- | --- | --- | --- |
| `.docx` | 是 | OOXML 文本、标题和表格分段 | 复杂浮动排版、批注、修订和嵌入对象不保证像素级还原 |
| `.rtf` | 是 | 流式文本化 | 复杂 RTF 控制字和嵌入对象可能降级 |
| `.doc` | 回退 | 保留原件后交给系统 Office/LibreOffice | 不在应用内实现不完整的二进制 Word 排版器 |
| `.xlsx` / `.xls` / `.xlsb` / `.ods` / `.csv` | 是 | 独立 Worker，工作表/行按需读取 | 读取单元格值与公式结果；宏、图表、透视图不执行 |
| `.pptx` | 是 | 幻灯片目录 + 当前页 | 文本与基础几何布局；主题媒体和动画逐步增强 |
| `.odp` | 是 | 幻灯片目录 + 当前页 | 语义文本预览，复杂母版不保证像素级还原 |
| `.ppt` | 回退 | 保留原件后交给系统 Office/LibreOffice | 不在应用内实现不完整的 OLE 演示排版器 |
| `.pdf` | 是 | WebView2 原生 PDF 引擎 | 依赖系统 WebView2 PDF 能力；安装版已携带离线 Runtime 安装组件 |

“打开”与“编辑”明确分离：Office/PDF 为只读查看，Markdown 仍保留阅读、源码、分栏、实时编辑、导出与 Agent 写入。这样可以避免第三方格式写回造成不可逆损坏。

## 文件留存

历史索引版本从 1 升级到 2，并为每项记录 `documentKind` 和原始快照扩展名。旧索引缺少字段时自动按 Markdown 迁移，原有 `{id}.md` 快照路径保持不变。

Office/PDF 使用 `{id}.{原扩展名}` 保存原始字节。历史或收藏再次打开时只读保留副本，不依赖源路径；清除历史仅删除未收藏项及对应快照。用户选择“保存到我的文档库”时，二进制快照按原文件名复制，不进行格式转换。

## 安全和资源边界

- 所有 Office 内容视为不可信输入，在 Worker 中解析；返回 React 的内容全部作为文本节点渲染，不注入文档 HTML。
- OOXML/ODF 只解压需要的 XML，累计上限为 96 MB，降低 ZIP bomb 风险。
- 单文件读取上限为 512 MB；表格显示列上限为 160，但原件不被修改。
- 不执行 VBA、宏、外部链接、嵌入脚本、PowerPoint 动画或公式代码。
- SheetJS 使用 0.20.3 修复版本并隔离在 Worker；npm 依赖审计在 0.7.6 开发时为 0 个已知漏洞。
- Tauri CSP 只为本地 asset protocol 开放 Worker/fetch/PDF frame；`object-src` 继续禁用。

## Release 验证

每个候选版本至少需要完成：

- `npm run typecheck`
- `npm test`（包含 DOCX/XLSX/PPTX 内存夹具）
- `npm run build`
- `npm audit --omit=dev`
- Windows `cargo test` 与 portable feature 测试
- Windows NSIS 离线 WebView2、LZMA、current-user 配置校验
- 真实 Office/PDF 语料的冷启动、热切换、源文件删除后重开、收藏后清除历史测试

性能基准必须记录硬件、系统、WebView2 版本、文件大小、页/行/幻灯片数量、冷/热状态和 P50/P95；否则数据不可比较。
