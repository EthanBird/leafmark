# LeafMark Agent 本地版本控制

LeafMark 的 Agent 版本控制不依赖 Git，也不会在文档库中创建 `.git`。它把一次用户消息、Agent 回复和本轮产生的全部本地文件变化视为一个原子回合。

## 行为模型

- **Lane**：一个 Agent 会话。
- **Turn / Burst**：一条用户消息到本轮 Agent 结束。
- **Draft patch**：本轮文档工具或 PowerShell 造成的文件差异。
- **全局时间线**：同一文档库的多个会话共享一条文件版本链，避免两个会话各自回退后互相覆盖。

发送消息前，LeafMark 会先保存编辑器内容并建立完整检查点。Agent 正常完成、失败或被停止后都会提交本轮版本；失败命令已经写入的部分内容同样可以回退。

撤销默认同时移动消息和文件。重做直接恢复记录的 `after` 字节，不会重新运行 PowerShell，也不会重复网络或其他命令副作用。回退较早消息时，会按全局时间线依次回退它之后的版本。

## 存储

版本数据位于 LeafMark 应用数据目录的 `agent-vcs` 中：

```text
agent-vcs/
  index.json       # 工作区 head、redo 游标、回合差异和 pending 事务
  objects/         # SHA-256 内容寻址的不可变原始字节
  recovery.json    # 多文件恢复过程的写前记录（仅恢复期间存在）
```

每个文件以原始字节计算 SHA-256，因此 UTF-8、BOM、CRLF、图片和其他二进制内容都能精确恢复；相同内容只保存一次。新增、修改、删除、重命名和空目录变化由前后清单推导，重命名在恢复层等价为删除旧路径并创建新路径。

外部 Markdown 使用 `archive:<id>` 逻辑资源加入同一版本；撤销只修改 LeafMark 保留副本，绝不写回微信临时文件等原始来源。

## 一致性与冲突

恢复前会验证受影响文件仍等于本轮记录的 `after`（撤销）或 `before`（重做）。如果用户、同步软件或其他程序后来又修改了文件，LeafMark 会停止恢复并报告冲突，不会静默覆盖。

恢复成功后，应用会清空旧自动保存任务，重新扫描文件树，并从磁盘重载所有打开标签。消息游标只在原生文件事务成功后移动，因此不会出现“消息已经撤销但文件没有撤销”的假状态。

未完成回合会先以 `pending` 状态原子写入索引。LeafMark 意外退出后，下次启动会把当前磁盘状态作为恢复后的 `after` 快照提交，使崩溃前的修改仍有归属并可回退。

## 当前安全边界

- 只保证当前 LeafMark 文档库和当前 LeafMark 保留副本中的文件变化。
- PowerShell 仍不是 Windows 沙箱；文档库外的绝对路径、注册表、数据库、网络服务等副作用无法靠文件快照撤销。
- 为保证版本边界完整，Agent 的终端工具当前只以前台方式执行，禁止后台或脱管进程。
- 遇到符号链接、Windows 重解析点、特殊文件、超过 20,000 个文件或总计 1 GiB 的工作区时，本轮会在模型或命令执行前拒绝启动，而不是产生无法完整回退的修改。
- 多文件切换不是 NTFS 的单条原子指令；LeafMark 使用逐文件原子写入、写前恢复记录和失败回滚，提供应用层的一致恢复。

## 操作入口

- Agent 顶栏的撤销、重做按钮操作全局最新版本。
- 每个 Agent 回复底部的“本地版本”卡片列出新增、修改和删除路径。
- “回退本轮”同时回退该轮消息与文件；较旧卡片上的“回退到这里”会先依次回退后续版本，并把原用户消息放回输入框。
- 撤销后发送新消息会建立新分支，并结束旧 redo 链。
